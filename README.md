# 官方 PK 活动管理后台

基于现有官方 PK 后台样式的交互前端，保留活动查询、新增、编辑、删除、分组。

## 代理消息通知

- 通知开关默认关闭；开启后需要配置多语言 Key、推送频次、首次推送时间。
- 频次：仅一次（默认）、每日一次（每 24 小时）、自定义间隔（6～720 的整数小时）。
- 北京时间 UTC+8，首次推送时间必须在活动结束前；重复推送到活动结束时终止。
- 列表新增推送频次、首次推送时间、下次推送时间；代理通知状态支持未开启、待推送、推送中、已完成、已过期、推送失败。
- 不含频次字段的历史活动按仅一次解释，不会自动重复推送。
- 每场活动的发送计数由服务端回写 `notifySentCount` 和 `notifyStatus`，前端不会模拟真实发送。

## 测试发送

点击活动数据列表「操作」列的「测试发送」，输入测试接收人 ID；发送语言自动使用接收人的语言设置，无需人工选择。前端调用：

`POST /api/pk-notification/test-send`

```json
{
  "pkId": 108,
  "notifyKey": "pk_agent_reminder",
  "recipientId": "123456",
  "locale": "auto"
}
```

服务端实际完成消息送达后才应返回如下成功应答：

```json
{ "success": true, "messageId": "provider-message-id" }
```

测试推送**不得**创建正式定时任务、增加正式发送次数、修改通知状态。失败须返回非 2xx 和错误文本。当前仓库无消息 API 实现，未接入现有推送服务时会明确报告接口不可用，不会误报成功。
